# Nueva Página ASPX en WebSGV

## Regla fundamental

Toda nueva página requiere **exactamente tres archivos** y **registro en el .csproj**. Sin esto, la página no despliega.

## Paso 1 — Crear los tres archivos

Ubicación: `WebSGV/Views/NombrePagina.aspx` (y sus compañeros).

### `NombrePagina.aspx`

```aspx
<%@ Page Title="Título de la Página" Language="C#" MasterPageFile="~/Site.Master"
    AutoEventWireup="true" CodeBehind="NombrePagina.aspx.cs"
    Inherits="WebSGV.Views.NombrePagina" %>

<asp:Content ID="BodyContent" ContentPlaceHolderID="MainContent" runat="server">
    <h2>Título</h2>
    <!-- contenido aquí -->
</asp:Content>
```

### `NombrePagina.aspx.cs`

```csharp
using System;
using WebSGV.Helpers;

namespace WebSGV.Views
{
    public partial class NombrePagina : System.Web.UI.Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
            // 1. Verificar sesión activa
            if (Session["UsuarioID"] == null)
            {
                Response.Redirect("~/Views/Login.aspx");
                return;
            }

            // 2. Verificar rol autorizado
            string rol = Session["Rol"]?.ToString().Trim().ToUpper() ?? "";
            if (!RolesHelper.TienePermiso(rol, "NombreSeccion"))
            {
                Response.Redirect("~/Views/Inicio.aspx");
                return;
            }

            if (!IsPostBack)
            {
                CargarDatos();
            }
        }

        private void CargarDatos()
        {
            // lógica de carga inicial
        }
    }
}
```

## Paso 2 — Registrar en WebSGV.csproj

Abrir `WebSGV/WebSGV.csproj` y agregar en los item groups correspondientes:

```xml
<!-- Grupo <Content> — para el .aspx -->
<Content Include="Views\NombrePagina.aspx">
  <DependentUpon>NombrePagina.aspx.cs</DependentUpon>
</Content>

<!-- Grupo <Compile> — para los .cs -->
<Compile Include="Views\NombrePagina.aspx.cs">
  <DependentUpon>NombrePagina.aspx</DependentUpon>
  <SubType>ASPXCodeBehind</SubType>
</Compile>
<Compile Include="Views\NombrePagina.aspx.designer.cs">
  <DependentUpon>NombrePagina.aspx</DependentUpon>
</Compile>
```

> Busca entradas existentes de otras páginas en Views\ para encontrar exactamente dónde insertar.

## Paso 3 — Control de acceso por roles

Usar siempre `RolesHelper` (en `WebSGV/Views/RolesHelper.cs`, namespace `WebSGV.Helpers`):

```csharp
// Verificar si el rol tiene permiso para una sección
RolesHelper.TienePermiso(rol, "NombreSeccion")

// O validar y redirigir automáticamente
RolesHelper.ValidarAccesoSeccion(this, rol, "NombreSeccion");
```

Roles reconocidos: `ADMIN`, `CONDUCTOR`, `SUPERVISOR`, `ADMINISTRADOR DE GRIFO`, `ADMINISTRADOR DE MAQUINARIA`, `OPERADOR`.

**Nunca** comparar roles con strings inline — siempre via `RolesHelper`.

## Paso 4 — Convenciones

- Nombres de archivos y clases en **PascalCase español**: `RegistroChoferes`, `BuscarFactura`, `AgregarOrdenViaje`
- Texto de UI en **español (es-PE)**
- Fechas y decimales via `FechaHelper.cs` y `NumeroALetrasHelper.cs`
- Auditoría de operaciones via `AuditoriaHelper.cs`
- Hashing de contraseñas via `PasswordHelper.cs` / `HashHelper.cs` — nunca implementar uno nuevo

## Paso 5 — Verificación

```powershell
# Verificar que el build no tiene errores tras agregar los archivos
msbuild WebSGV.sln /p:Configuration=Debug /nologo /verbosity:minimal
```

Luego abrir la página en IIS Express y confirmar:
- [ ] Carga sin error 500
- [ ] Redirige a Login si no hay sesión
- [ ] Redirige a Inicio si el rol no tiene acceso
- [ ] Datos cargan correctamente en `!IsPostBack`
